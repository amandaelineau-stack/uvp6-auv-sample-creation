# ALR UVP6 Processing

Scripts for processing the UVP6 data of the ALR (Autosub Long Range) platform.

The protocol of the pipeline will be published in the [Ocean Best Practices System](https://repository.oceanbestpractices.org) (DOI: to be assigned).
It has been tested only with data generated by the ALR platform.
A demonstration project, `ALR4_demo`, can be downloaded from the [ALR4_demo release](https://github.com/amandaelineau-stack/ALR_UVP_Processing/releases/download/ALR4_demo/ALR4_demo.zip) (233 MB zip: ALR CTD and NAV files and a complete UVP6 project).

## Quick start: the app

The pipeline can be run from an app in your web browser, with no code to edit (Windows).
GitHub only stores the code: the app runs on your own computer, on your own data, and nothing
is sent anywhere.

### Once: install

1. **Download the code**: click the green **Code** button at the top of this page, then
   **Download ZIP**, and extract the zip, e.g. to `C:\ALR\ALR_UVP_Processing`.
2. **Download the demo data** (optional, to try the app): [ALR4_demo.zip](https://github.com/amandaelineau-stack/ALR_UVP_Processing/releases/download/ALR4_demo/ALR4_demo.zip)
   (233 MB), and extract it to a short path, e.g. `C:\ALR\ALR4_demo`.
   Windows cannot write files whose path is longer than 260 characters, which a deeply nested
   folder (e.g. in OneDrive) can reach: the app warns you if so.
3. **Install Miniconda** (free, it installs Python): download it from
   [anaconda.com/download](https://www.anaconda.com/download/success) (*Miniconda* installer for
   Windows) and install it with the default options: "Just Me", and keep
   **Create shortcuts** ticked, which adds **Anaconda Prompt** to the Windows Start menu.
4. **Create the environment of the app**: open **Anaconda Prompt** from the Start menu (click
   Start and type "Anaconda Prompt", or find it under *Anaconda3 (64-bit)* or *Miniconda3* in the
   list of apps). It is a black window where commands are typed. Type these two commands, each
   followed by Enter:
   ```
   cd C:\ALR\ALR_UVP_Processing
   conda env create -f environment.yml
   ```
   (the first one goes to the code folder of step 1). This downloads Python 3.12 and the packages
   of the pipeline, in an environment called `alr_uvp`, in a few minutes. Then close the window.
5. **Desktop shortcut** (optional): double-click [`create_shortcut.bat`](create_shortcut.bat) in
   the code folder. It puts an **ALR-UVP6 app** shortcut on your desktop, which starts the app
   (it does the same as `start_app.bat`). If you move the code folder, run it again.

### Every time: run

1. **Start the app**: double-click the **ALR-UVP6 app** shortcut on your desktop, or
   [`start_app.bat`](start_app.bat) in the code folder. A black
   window opens (the first time, it installs the app in about a minute), then the app opens in
   your web browser, at http://localhost:8501. Keep the black window open while you use the app;
   close it to stop the app.
2. **Data**: click **Browse…** next to *Deployment folder* and choose the folder of the deployment,
   e.g. `C:\ALR\ALR4_demo`. The app finds the ALR CTD and NAV folders, the UVP6 project and the
   figures folder in it, and checks them: each line must be green.
3. **Settings**: check the ALR serial number (found from the folder names), the cruise and the
   sample integration.
4. **Run**: click **Run the pipeline**. Each step is shown as it runs (a few minutes for a long
   deployment).
5. **Results**: download the sample file, and look at the phase checks, the quality checks and
   the figures. The app writes the same files as the script: the sample file and the CTD files in
   the UVP6 project, the figures in the figures folder (see [Outputs](#outputs)).

The address http://localhost:8501 only works on the computer running the app. To share the app
with a colleague, share this repository: they install it and run it on their own computer.

If the black window shows "python is not recognized", Miniconda was not found: open Anaconda
Prompt and type `conda activate alr_uvp`, then `cd C:\ALR\ALR_UVP_Processing` and
`python -m streamlit run app.py`.

## The script

[`run_UVP_toolbox.py`](run_UVP_toolbox.py) runs the UVP6 data processing workflow:

1. **Load and parse the ALR data (CTD and NAV)**
2. **Identify the ALR phases (profiles, transects, transitions) from the CTD and NAV data**
3. **Generate one netCDF file per ALR phase**
4. **Generate one sample file compatible with UVPapp (header file)**

The same four titles are used for the cells of the script, below and in the documentation.

## Setup

Tested with Python 3.12 (Miniconda) on Windows, with the packages in
[`environment.yml`](environment.yml):

```bash
conda env create -f environment.yml
conda activate alr_uvp
```

or, in an existing environment, `pip install -r requirements.txt`.

VS Code is recommended. Install its **Python** and **Jupyter** extensions (Microsoft):
the Jupyter extension, with the `ipykernel` package of the environment, gives the
**Run Cell** buttons used below. Select the `alr_uvp` environment as the Python interpreter.

## Before you run

### 1. Close UVPapp
Close UVPapp before running, so that it does not have the project open while cell 4 writes
the sample file and the CTD files.

### 2. Structure the ALR directories
One folder of CTD `.log` files and one folder of navigation `.csv` files. Every file
directly inside each folder is read and merged; subfolders are ignored.

```
<parent_directory>/
├── <alr_serial_number>_ctd_data/
│   └── *.log
└── <alr_serial_number>_nav_data/
    └── *.csv
```
e.g. `ALR004_ctd_data/` and `ALR004_nav_data/` in `ALR4_demo`, next to the UVP6 project folder.
In future releases, the ALR CTD and NAV data will come in a single netCDF file.

### 3. Structure the UVP6 project directories
The UVP6 sequences in `raw/`, in a project created with UVPapp:

```
<parent_directory>/
└── uvp6_<uvp6_serial_number>_<first_deployment_date>_<cruise_name>_<platform><platform_serial_number>/
    └── raw/<yyyymmdd-HHMMSS>/<yyyymmdd-HHMMSS>_data.txt
```
UVPapp sets this name when the project is created. `<first_deployment_date>` is the start date
of the deployment (`yyyymmdd`), not the date the project was created, e.g.
`uvp6_sn000227lp_20240807_dy180_biocarbon1_alr4`.

The project must be complete, with all the UVPapp folders (`calibration`, `config`, `CTDdata`, `doc`,
`ecodata`, `livecamera`, `log`, `meta`, `raw`, `results`), as `ALR4_demo` is: the pipeline does not
create them, and cell 3 stops with the list of the missing ones.

When the UVP6 restarted during the deployment, merge its sequences in UVPapp first: the
pipeline uses the merged sequence (`_Merged-NNN`) and ignores the originals (`_UsedForMerge`).

A folder for the figures is created if it does not exist, e.g. `<parent_directory>/diagnostic_figures/`.

### 4. Processing settings
At the top of [`run_UVP_toolbox.py`](run_UVP_toolbox.py):

| Setting | What it does |
| --- | --- |
| `ALR_SERIAL_NUMBER` | ALR serial, e.g. `4` becomes `ALR004`. Names the netCDF files and the `meta/alr_meta_sn004` folder. |
| `CRUISE` | Cruise name, written to the sample file. |
| `OUTPUT_DIR` | Folder for all figures. `None` asks with a dialog. |
| `PHASE_DETECTION` | Thresholds of the phase detection (any other `alr_data.detect_profiles` parameter can be added). The same values are drawn on the phase detection figure. |
| `DEPTH_INTEGRATION` | `integrationtime` of the depth-integrated samples (`P`: downcasts, upcasts, transitions), in m. 5 by default. |
| `TIME_INTEGRATION` | `integrationtime` of the time-integrated samples (`T`: transects, surface transects), in s. 3600 by default. |
| `UVP_PROJECT_DIRS` | Folders of a UVPapp project (`calibration`, `config`, `CTDdata`, `doc`, `ecodata`, `livecamera`, `log`, `meta`, `raw`, `results`), checked in cell 3. |

In cell 4, `assume_yes=False` asks before replacing an existing sample file;
`True` replaces it without asking.

## Run

### With the app (no code to edit)

Double-click [`start_app.bat`](start_app.bat) (or run `python -m streamlit run app.py` in the
`alr_uvp` environment). The app opens in the web browser, and runs on this computer only:

1. **Data**: choose the deployment folder (as `ALR4_demo`); the ALR CTD and NAV folders, the UVP6
   project and the figures folder are found in it, and checked (files found, complete UVPapp
   project, one merged sequence).
2. **Settings**: ALR serial number, cruise, sample integration and, if needed, the phase detection
   thresholds.
3. **Run**: the four cells below, one after the other.
4. **Results**: the sample file (to download), the phase checks, the quality checks and the figures.

The app writes the same files as the script.

### With the script

Open `run_UVP_toolbox.py` in VS Code and click **Run Cell** above each `# %%`
marker, in order; the cells run in an Interactive Window. To run it all at
once instead: `python run_UVP_toolbox.py` in a terminal.

| Cell | Asks for (in order) | What happens |
| --- | --- | --- |
| 0. Setup | – | Imports and settings. |
| 1. Load and parse the ALR data (CTD and NAV) | CTD folder, NAV folder, figures folder | Reads and merges the CTD and NAV files. |
| 2. Identify the ALR phases | – | Detects the phases; displays and saves two figures and prints the phase checks (see [Quality-control figures](#quality-control-figures)). |
| 3. Generate one netCDF file per ALR phase | UVP6 project folder | Checks the project folders; writes one netCDF per ALR phase in `meta/alr_meta_sn004/`. |
| 4. Generate the UVPapp sample file | Yes/No if a sample file exists | Matches the UVP6 images to the ALR phases; writes the sample file, the CTD files, the diagnostic and quality-check figures. |

Figure windows open one at a time: close each one to continue.

Near the end of cell 4, two lines summarise the matching:

- `Matching UVP data times were not found for X of Y CTD/NAV files`: ALR
  phases with no UVP6 image in their time window.
- `Matching CTD/NAV files were not found for X of Y UVP images`: UVP6 images
  outside every matched phase.

## Outputs

```
<UVP6 project>/
├── config/cruise_info.txt                    # created if missing (cell 3)
├── meta/
│   ├── alr_meta_sn004/*.nc                   # one per ALR phase (cell 3)
│   ├── alr_meta_sn004/archives/<date>/*.nc   # netCDFs of the previous run (cell 3)
│   ├── uvp6_header_<project>.txt             # UVPapp sample file (cell 4)
│   └── archives/uvp6_header_<project>_<date>.txt   # previous sample files (cell 4)
└── CTDdata/<phase>.ctd                       # one per matched phase (cell 4)

<figures folder>/
├── ALR004_phase_detection.png                # cell 2
├── ALR004_phase_sectioning.png               # cell 2
├── uvp_alr_timedepth.png                     # cell 4, and below
├── uvp_alr_timedepth_fullspan.png
├── uvp_alr_sampling_intervals.png
├── daily_plots/uvp_alr_timedepth_<date>.png
├── overview_plots/uvp_alr_timedepth_all_days.png
├── uvp_alr_depth_agreement.png               # cell 4, quality checks
├── uvp_alr_coverage_map.png
├── uvp_alr_sample_sizes.png
├── qc_coverage.csv
└── qc_summary.txt
```

The ALR netCDFs are saved in `meta/`, with the sample file: `raw`, `config` and `meta` are
the folders needed for the science, and the ones backed up at some institutes. Projects
processed before, with the netCDFs in `doc/alr_meta_sn004/`, are still read.

Each phase netCDF holds `TIME`, `DEPTH_SCI` (CTD pressure), `DEPTH_ENG`, `DEPTH_SCI_INTERP`,
`LAT`, `LON`, `TEMPERATURE`, `CONDUCTIVITY`, `OXYGEN`, `PITCH_ENG` and `ROLL_ENG`. The CTD
files fill the UVPapp columns time, depth, pressure, temperature and conductivity, followed
by all the netCDF variables.

In the sample file, downcasts, upcasts and transitions are depth-integrated samples (`P`,
`integrationtime` = `DEPTH_INTEGRATION`), transects and surface transects time-integrated
samples (`T`, `integrationtime` = `TIME_INTEGRATION`).

Cell 1 saves the merged ALR data to `_cache_big_df.parquet` in the repository directory.

### Quality-control figures

Phases are coloured as in the documentation: d downcast (blue), u upcast (orange),
t transect (green), s surface transect (yellow), x transition (dark grey).

| Figure | What it shows | What to check |
| --- | --- | --- |
| `ALR004_phase_detection.png` | Depth, the two detection criteria (smoothed vertical velocity, and M = −pitch × vertical velocity) with their thresholds as grey bands, the pitch, and the profile numbering before/after the duration and back-fill filters. | Why a record got its phase; whether the thresholds suit the deployment. |
| `ALR004_phase_sectioning.png` | The deployment coloured by phase, the count of each phase type, and one block per phase (one phase = one netCDF file = one sample), with the segment boundaries. | Each dive split into a downcast and an upcast, no missed profile, no fragmented transect. |
| `uvp_alr_timedepth.png`, `…_fullspan.png`, `daily_plots/`, `overview_plots/` | UVP6 (dots) and ALR (line) depth, the UVP − ALR depth difference (10 s medians), and, in `…_fullspan.png`, the ALR → UVP clock offset of each 31 × 10 s window, coloured by r²; the median over reliable windows (r² ≥ 0.9) is printed and drawn. The ALR depth is drawn over the whole deployment, and the gaps of the coverage map are shaded red. | A constant depth difference points to a pressure offset, a difference growing with depth to a scale difference, and a non-zero median offset to a clock offset. |
| `uvp_alr_sampling_intervals.png` | Distribution of the time between two UVP6 images and two ALR records. | Gaps or irregular sampling. |
| `uvp_alr_depth_agreement.png` | UVP − ALR depth against ALR depth (10 s medians), with the fit UVP − ALR = scale × depth + offset + lag × vertical velocity, over the deployment and per day. | A WARNING when \|scale\| > 0.5 %, \|offset\| > 0.5 m or \|lag\| > 1 s. A scale near +1.97 % is what a UVP depth in mH₂O against an ALR pressure in dbar gives. A lag that grows day after day is a drifting clock. |
| `uvp_alr_coverage_map.png` | The ALR track seen from above, coloured by phase type where the UVP6 has images and red where it has none, with the time and position where each gap starts and ends; below, every phase on a time line. | Where and when the UVP6 did not record. A gap runs from the last UVP6 image before it to the first one after it, and is listed when it lasts 1 h or more (`MIN_GAP_HOURS` in `qc.py`). |
| `uvp_alr_sample_sizes.png` | Images per sample, by phase type, with the `qc_min_images` limit of `create_samples` (20 by default). | Very small samples, usually transitions, not worth processing in UVPapp. |

The quality checks of cell 4 are also printed and written to `qc_summary.txt`: the depth agreement, the deployment
(start, end, track length), a table of the phases by type (number, number with images, images) and the gaps. The
gaps are also in `qc_coverage.csv`: start and end time, duration, start and end position, track length and the
phases by type. Cell 2 prints the
phase checks of `alr_plots.check_phases`: the duration of each phase type, a warning for a segment
without an upcast, and a warning for a transition longer than 30 min.

## Re-running

- **After editing code in `main/` or `UVP_toolbox_Python/`**, restart the
  interactive window's kernel.
- **Cell 3** moves the netCDFs of the previous run to `meta/alr_meta_sn004/archives/<date>/`
  before writing the new ones, as cell 4 matches every `.nc` file of `meta/alr_meta_sn004/`.
- **Cell 4** moves the previous sample file to `meta/archives/`, with a `_YYYYMMDD-HHMMSS`
  suffix, as UVPapp does when the metadata are edited.
